winpe_terminal 用户文档
========================
本项目是一个基于windows pe虚拟机的一个项目，可以在设备支持时，为linux系统启动基于kvm虚拟化技术的qemu windows pe虚拟机，并通过终端透传的方式让用户便捷的进行控制和操作。
根据第三方许可证要求，本项目应当用于linux和windows双系统用户便捷的在linux系统下执行对于windows系统的恢复和维护工作，如调用chkdsk对windows分区进行ntfs分区修复。

请注意，如果您是普通用户，您需要知道windows pe不是常规意义上的完整的windows系统环境，绝大多数您熟悉的软件都无法运行，该软件常用场景也只是提供最基础的windows分区相关的维护和管理功能。
换言之就是启动一个windows pe 虚拟机，然后你就可以直接在终端里使用这个虚拟机的cmd(命令提示符)。
如果您不理解上述文本，请不要安装使用本项目。该项目的使用和操作有较高风险，请谨慎使用。

补充说明：
1.该项目运行方式是使用qemu和kvm启动一个windows pe虚拟机，然后通过EMS/SAC实现终端透传，从而让用户可以直接使用终端控制这个windows pe虚拟机。
2.我们支持使用参数挂载指定存储设备运行，这样您就可以在确认目标存储设备/分区处于未挂载前提下使用参数启动并挂载到虚拟机，具体使用方式请查看protocol/usage_protocol.md当中的说明。
3.tips：如果你希望使用chkdsk来修复目标分区，比如由于异常关闭导致windows分区处于dirty状态，你需要先使用命令查询对应分区的设备路径，然后按照要求使用这个设备路径参数化启动，这样，这个存储设备才会被windows pe虚拟机挂载上，你就可以使用chkdsk来修复它-而无需重启电脑中断你的工作。windows pe里面的cmd同样支持其他的一些命令，你可以按需使用
4.该项目需要从微软服务器上下载用于构建的一些资源，使用时请保持网络通畅。如果你位于中国大陆，安装时你遇到的网络问题应该主要在于第一步安装deb的过程，你可以自行通过镜像源等方式解决。
5.据说虚拟机启动需要大约半分钟到一分钟的时间，请稍安勿躁。如果你在prepare初始化过程等待了漫长的时间，那一般应该是微软服务器的网速较慢，也请稍安勿躁。
6.该项目虚拟机运行时需要大约1GB运行内存，项目本身也需要一定的存储空间，仅供参考。
7.SAC本身与常规的CMD运行环境有一定的区别，所以你可以看到终端的显示有时会出现一些bug,这是正常的，而且我不打算再投入精力修复或者说优化。
8.胡乱使用cmd是可以造成比较严重的后果的，加上你需要使用sudo（也就是最高管理员）权限运行，如果你挂载了不太合适的目录并且不慎造成了破坏性动作，可以对你的电脑系统造成很严重的后果，使用时务必小心。
9.本人不承担任何由本项目造成的后果，所以说如果是刚来使用linux的双系统用户，虽然这个项目已经是用内存里的虚拟机跑的了，但是还是要强调用的时候不要随便乱搞免得搞坏电脑，不要盲目听从豆包的“指导”。
